# Formalization backlog

[Documentation index](../README.md) · Proofs and formal reasoning

Narya's current assurance combines prose derivations, executable scalar
oracles, differential testing, range assertions, and native-hardware tests.
None of those artifacts is a machine-checked proof. This backlog identifies
claims that are both consensus-relevant and compact enough to be useful Lean
projects rather than open-ended verification programs.

## Tier 1: algebraic and finite-domain lemmas

### Radix-51 IFMA split, fold, and carry

Formalize `B = 2^51`, `p = 2^255 - 19`, five u52 source limbs, the low/high
split at bit 52, reconstruction of the radix-51 convolution, folding with
`B^5 ≡ 19 (mod p)`, and the parallel carry bounds. Desired theorems:

1. the output denotes the product modulo `p`;
2. no unsigned 64-bit intermediate overflows under the stated source bounds;
3. the carried output is again strictly below `2^52` per limb;
4. exact input/output aliasing is irrelevant to the functional result once
   the load-before-store trace is established separately.

The algebra should be proved independently of AVX-512. A second refinement
lemma can connect each `VPMADD52LUQ/HUQ` pair to the scalar split operation.

### Compressed-input classification

Formalize the permissive decoder's alias set and prove that the fourteen byte
strings generated by the seven low-255-bit constants and both sign bits are
exactly the encodings that decode to pure small-order points. Separately prove
the canonical-encoding rule `low255 < p` plus rejection of sign-bit-one at
`x = 0`, without relying on small-order-check ordering.

### Projective strict finalizer

For a valid projective point with `Z != 0`, prove that projective y equality
against the canonical bytes plus the canonical parity of affine x is
equivalent to byte-for-byte compressed encoding equality. Include the
negative-zero (`x = 0`, sign bit one) boundary explicitly.

## Tier 2: verification-equation theorems

### Exact strict predicate decomposition

Show that byte prechecks, permissive A decoding, canonical R handling,
small-order rejection, hashing the original bytes, and the final group
equation compose to the documented `DalekStrict` acceptance set. This theorem
should state decoder behavior explicitly rather than assume a mathematical
point is the input.

### HEEA modulo `8L`

Formalize the corrected relation

```text
[tau*s]B - [tau]R - [epsilon*rho]A
  = [tau]([s]B - R - [k]A)
```

under the exact integer relation modulo `8L`, and prove that odd `tau` with
`L ∤ tau` is a unit on the full Edwards group `G_L × T_8`. Keep selector
existence/bit-length bounds separate from group-equation exactness.

## Tier 3: implementation refinement

### Lane noninterference

Prove that the x8 field and point schedules are a map of one scalar program
over eight lanes. This needs a small semantics for the vector instructions
actually used, including masks and table transposes; merely proving the field
formula is insufficient.

### Assembly-to-model refinement

Connect the System V or Go-ABI instruction trace to the algebraic model,
including CPUID/XCR0 preconditions, register clobbers, load-before-store alias
safety, and absence of cross-lane data flow. Lean may be appropriate for the
arithmetic layer; a bitvector SMT certificate or an ISA semantics framework
may be more practical for the instruction layer.

## Questions to send for theoretical review

- What is the smallest reusable Lean abstraction for redundant radix limbs
  that preserves both field congruence and machine integer bounds?
- Should the IFMA refinement use an existing x86 semantics, or a reviewed
  local semantics for the small instruction subset?
- Can the decoder/canonicality proof reuse an existing Edwards25519
  formalization without importing a different decoder policy?
- Which exact security statement follows from the `DalekStrict` predicate,
  rather than from a nearby standardized Ed25519 variant?
